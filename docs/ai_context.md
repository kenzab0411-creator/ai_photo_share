# AI実装コンテキスト

## アプリの目的

友人同士で旅行や日常の写真を共有する、Instagram風の小規模Webアプリ。ユーザーは写真1枚と短いキャプションを投稿し、公開投稿にはいいね・コメントを付けられる。

## 確定事項

- 技術は Python、Flask、Peewee、SQLite。別のWebフレームワークやORMへ変更しない。
- Flaskアプリは初回版では `app.py` を中心としたシンプルな構成にする。Blueprintやアプリファクトリは導入しない。
- SQLiteデータベースは `instance/app.db` に置く。
- ユーザー投稿画像の保存先は、プロジェクト直下の `uploads/` とする。`static/` はCSS・JavaScriptなどの静的アセット専用とする。
- 画像は JPEG、PNG、WebP だけを許可し、最大サイズは5MBとする。
- ログイン状態はサーバー側セッションで管理し、ブラウザを閉じたら終了する。ログイン状態を長期保持する「remember me」機能は作らない。
- 登録情報はユーザー名とパスワードだけ。メールアドレスは保存・検証しない。
- キャプションは任意入力、最大200文字。
- 投稿は `public` または `private`。非公開投稿を見られるのは投稿者本人だけ。
- 検索とフォローは今回の対象外。

## 機能範囲

### 今回実装する

- ユーザー登録、ログイン、ログアウト
- 写真投稿、公開投稿一覧、投稿詳細
- 自分の非公開投稿一覧
- 自分の投稿の編集・削除（写真の差し替えはしない）
- 公開投稿へのいいねの追加・取り消し、いいね数の表示
- 公開投稿へのコメント追加、コメント一覧の表示

### 今回実装しない

- メールアドレス、パスワード再設定
- 検索、フォロー、通知
- 投稿の写真差し替え
- コメントの削除
- 本番向けクラウドストレージ

## データモデル

| モデル | 役割 | 主なフィールド・制約 |
| --- | --- | --- |
| `User` | 認証と投稿者の識別 | `username` は一意、`password_hash`、`created_at` |
| `Post` | 写真投稿 | `image_filename` は一意、`caption`、`visibility`、`user`、`created_at`、`updated_at` |
| `Like` | 誰がどの公開投稿をいいねしたか | `user`、`post`、`created_at`。`user` と `post` の組を一意にする |
| `Comment` | 公開投稿に付いたコメント | `user`、`post`、`body`、`created_at`。`body` は空不可 |

## 権限ルール

| 操作 | 未ログイン | ログインユーザー | 投稿者本人 |
| --- | --- | --- | --- |
| 公開投稿の一覧・詳細を見る | 可 | 可 | 可 |
| 非公開投稿を見る | 不可 | 自分の投稿だけ可 | 可 |
| 投稿する | 不可 | 可 | 可 |
| 投稿を編集・削除する | 不可 | 他人の投稿は不可 | 可 |
| 公開投稿にいいね・コメントする | 不可 | 可 | 可 |
| 非公開投稿にいいね・コメントする | 不可 | 不可 | 不可 |

他人の非公開投稿詳細は `404 Not Found`、他人の投稿の編集・削除は `403 Forbidden` を返す。

## ルーティング方針

- 表示は `GET`、作成・更新・削除・ログアウトは `POST`。
- 主なURLは `/`、`/register`、`/login`、`/logout`、`/posts/new`、`/posts/<int:post_id>`、`/posts/<int:post_id>/edit`、`/posts/<int:post_id>/delete`。
- `uploads/` は `static/` の外に置くため、`/uploads/<filename>` の `GET` ルートで安全に画像を配信する。投稿詳細・一覧ではこのURLを使う。
- 公開投稿へのいいねは `/posts/<int:post_id>/likes` の `POST`、取り消しは同URLの `POST` で現在の状態を切り替える。
- コメント追加は `/posts/<int:post_id>/comments` の `POST`。
- 投稿一覧の非公開タブは `/?visibility=private` を使い、未ログインなら `/login` へ移動する。
